Project Summary:

This project is a multi-tenant pharmacy management platform built with .NET Core, Entity Framework Core, and gRPC. It enables pharmacies to manage prescription transfers, customer data, inventory, and related workflows in a secure, scalable environment.

The backend is structured as a set of microservices, with gRPC APIs handling communication between services and clients. Entity Framework Core is used for data access, supporting advanced features like shadow properties and database triggers to ensure data integrity and auditability.

Authentication is managed via JWT tokens, with user and tenant context extracted from claims to enforce data isolation and security. The system supports audit fields (CreatedBy, UpdatedBy, etc.) and multi-tenancy (TenantId, TenantStoreId) to ensure each pharmacy’s data is kept separate and secure.

Key features include:

Secure, multi-tenant data management for pharmacies
Support for prescription transfer workflows
Integration with external systems via gRPC
Robust audit logging and error handling
Scalable architecture ready for cloud deployment
My role involved understanding and improving core business logic, fixing multi-tenancy and audit issues, and ensuring the system’s security and reliability.

1. .NET Core (C#) Fundamentals
What to Learn:

What is .NET Core? (A cross-platform framework for building applications)
C# basics: classes, interfaces, properties, methods, async/await, dependency injection.
Project structure: Solutions (.sln), projects (.csproj), folders.
How to Explain:
“.NET Core is the main framework for our backend. We use C# to write all our business logic, organize code into classes and interfaces, and use dependency injection to manage services and configurations.”

2. Entity Framework Core (EF Core)
What to Learn:

What is an ORM? (Object-Relational Mapper: maps C# classes to database tables)
Code-first approach: define models in code, generate DB schema via migrations.
DbContext: the main class for querying and saving data.
LINQ: a way to write queries in C#.
Shadow properties: properties in the DB but not in the C# class.
Migrations: how to update the database schema as code changes.
How to Explain:
“EF Core lets us work with the database using C# objects. We define our entities (like TransferPharmacy) as classes, and EF Core handles the SQL for us. We use migrations to keep the database schema in sync with our code.”

3. gRPC
What to Learn:

What is gRPC? (A high-performance, strongly-typed way for services to talk to each other)
Protobuf: the language for defining messages and services.
How to define a service and implement it in C#.
How gRPC differs from REST (binary, faster, contract-first).
How to Explain:
“gRPC is how our services communicate. We define service contracts in .proto files, generate C# code, and implement the logic. It’s faster and more efficient than REST, especially for internal service-to-service calls.”

4. SQL Server & Database Triggers
What to Learn:

What is SQL Server? (A relational database)
Tables, columns, primary keys, foreign keys.
What is a trigger? (A piece of code that runs automatically when data changes)
Why triggers can cause issues with EF Core (OUTPUT clause error).
How to Explain:
“We use SQL Server to store our data. Some tables have triggers, which are bits of code that run when rows are inserted or updated. EF Core needs to know about these triggers to avoid certain SQL errors.”

5. Multi-Tenancy
What to Learn:

What is multi-tenancy? (Supporting multiple customers/organizations in one app)
How TenantId and TenantStoreId are used to separate data.
How EF Core filters data by tenant.
How to Explain:
“Our app supports multiple pharmacies (tenants). Each record has a TenantId and TenantStoreId, so data is always filtered to the right organization. This keeps data secure and separated.”

6. Authentication & Authorization (JWT)

“We use JWT tokens for authentication. When a user logs in, they get a token with their info. The backend reads this token to know who the user is and what data they can access.”
